# 행사 전 실제 AI 상담 연결

2026-11-02. 중은 님의 회신에 따라 고객 AI 상담을 우선 연결한다. 화면은 기존 Luminous Operate 모드를 유지한다.

## 회신으로 확인된 범위

- 원본 운영 기준은 `e1a57c2`, 직전 백엔드 변경은 `b8509a9`. `main`과 `import-credigraph`가 같은 상태라는 회신이며, 원격 Git에서도 `e1a57c2`를 확인했다.
- DB 0065까지 적용되었다는 내용은 담당자 회신 기준이다. DB를 직접 조회하거나 변경하지 않았다.
- 프로토타입 도메인의 CORS 및 Supabase 콜백을 허용했다고 회신했다. CORS는 OPTIONS 응답에서 별도로 확인했다. 실제 로그인 콜백은 이번 범위에서 검증하지 않았다.
- AI 상담은 필수. 로그인은 선택, 서버 대화 저장은 선택이며 브라우저 저장 유지 가능. 전문가 사례·공유 승인·상담방은 샘플 유지.
- 공개 행사 URL은 `https://neo-luddite.vercel.app/r/kintex`. 프로토타입 통계 추가 작업은 요구하지 않았다.

## 구현 방식

전체 앱을 live로 전환하면 전문가 저장·공유·상담방도 서버 연결이 활성화되므로, 별도 고객 상담 플래그를 추가한다.

```dotenv
NEXT_PUBLIC_DATA_MODE=prototype
NEXT_PUBLIC_ENTRY_CHAT_MODE=live
NEXT_PUBLIC_API_BASE=https://158-179-177-51.sslip.io
```

이 조합에서는 고객 채팅만 `/api/chat`에 POST한다. Supabase, 전문가·관리자 API, 계정 로그인은 기존 로컬 데모를 유지한다. 실제 로그인과 서버 대화 저장은 이번 구현에서 제외했다. Supabase 키가 없어도 고객 상담을 사용할 수 있다. `NEXT_PUBLIC_*`는 빌드 시점 설정이므로 환경변수 변경 후 재빌드해야 한다.

플래그가 없으면 기존 오프라인 프로토타입이 유지된다. `NEXT_PUBLIC_DATA_MODE=live`의 기존 전체 연동 경로도 유지한다. 고객 live 대화는 기존 샘플과 별도 브라우저 저장 키를 사용한다.

## 대화 계약과 오류 처리

- 요청에는 conversationId, occupation, history, userInput을 보낸다.
- 응답의 알려진 화면 필드는 검증하되, 원본 assistant 객체와 중첩 필드·ID·order·추가 서버 필드는 제거하거나 덮어쓰지 않는다. 브라우저 재접속 후에도 그대로 history에 전달한다.
- meta.congested 또는 최상위 congested가 true이거나 HTTP 429이면 혼잡 안내를 표시한다. 혼잡 안내를 정상 assistant 답변으로 저장하지 않는다. 질문은 유지하며 수동 재시도 시 사용자 메시지를 중복 추가하지 않는다.
- 대기 중 예상 소요 시간 10~20초와 혼잡 시 지연 가능성을 표시한다. 90초 타임아웃과 재시도 안내를 둔다.
- 실제 AI 답변에 ‘샘플 응답’ 표시를 붙이지 않는다. 전문가 연결 제안은 실제 접수 버튼 대신 샘플 체험이라는 설명으로 표시한다. 이 모드에서는 자동 대화 저장이나 상담 신청을 실행하지 않는다.
- 대문·소개·대화·사이드바에서 실제 AI 상담과 샘플 계정·전문가 기능의 범위를 구분한다.

## 검증

- 새 서비스·저장 테스트에서 기존 동작의 실패를 재현한 후 수정했다. 채팅 전용 연결, 나머지 Supabase 읽기의 로컬 유지, 원본 응답의 중첩 필드 보존, 재접속 후 history 재전송, 혼잡 후 재시도와 중복 방지를 검사한다.
- 단위·서비스 테스트 123개 통과.
- 고객 상담만 live인 production build 통과. 브라우저 검증에는 `http://localhost:8799`를 합성 API로 사용했다.
- Chromium에서 대기 표시 → 혼잡 → 재시도 → 실제 응답 형식 표시 → 새로고침 → 다음 질문의 원본 history를 확인했다. 가로 1440px와 390px 화면을 확인했고 모바일 가로 넘침은 없었다. 이 검증에서는 채팅 이외 API 요청이 없었다.
- 운영 API CORS: 프로토타입 Origin의 OPTIONS 요청이 HTTP 200과 일치하는 allow-origin을 반환했다.
- 운영 API 연속 2턴: 가상의 병의원 직원 식대 질문과 추가 설명으로 실제 프론트 chat 서비스를 호출했다. 두 응답이 계약 검증을 통과했고, 첫 assistant 객체를 다음 history에 전달했다. 총 약 12.5초. 이는 응답 연결 확인이며 세무 답변 정확도 평가가 아니다.
- DB 직접 쓰기·마이그레이션·실제 로그인·서버 대화 저장은 하지 않았다. 채팅 호출에 따른 운영 서버 내부 계측 여부는 이 검증에서 통제하지 않았다.

## 반영 시 확인

`frontend/vercel.json`의 buildCommand가 VERCEL_ENV=production인 배포에서 위 세 값을 설정한다. 기본 로컬 빌드와 Preview 배포는 기존 환경 설정을 따른다. 기존 Supabase 설정이 있어도 운영 빌드의 DATA_MODE=prototype을 유지한다. 배포 후 실제 도메인에서 로그인 없는 질문, 대기·재시도, 재접속, 전문가 체험의 로컬 유지를 확인한다. 롤백은 vercel.json의 ENTRY_CHAT_MODE=live를 prototype으로 바꾸고 재배포하면 된다.

이 문서는 코드와 로컬 검증 기록이다. 별도 배포 성공 기록이 없다면 공개 프로토타입 반영 완료로 해석하지 않는다.
